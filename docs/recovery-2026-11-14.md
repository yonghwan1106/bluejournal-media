# 기사 자동화 복구 기록 (2026-11-14)

## 확인한 상태
- 일반 기사 수집·발행은 기존 서버 작업 유지.
- 세계 자치모델: 발행 기사 22편, 마지막 발행 2026-10-28. 기존 서버 소스에는 전용 예약 작업 없음.
- 특집: 예약 작업은 살아 있었지만 10월 말부터 주제 선정 검증에서 반복 보류. 제목에 검색어 2~4개가 공통으로 들어 있어야 한다는 조건이 실제 관련 자료까지 탈락시킴.
- GitHub main과 운영 배포본 차이는 홈 화면과 기사 조회 파일 두 개. 운영 배포본에서 복원하고 SHA-1이 일치함을 확인한 후 이번 소스에 포함.

## 운영 시간 (한국 시간)
| 작업 | 생성 | 재시도 | 발행 |
|---|---|---|---|
| 세계 자치모델 | 수요일 07:00 | 08:00, 08:30 | 09:00 |
| 경기 주간 특집 | 토요일 07:00 | 08:00, 08:30 | 09:00 |

검수 통과 기사만 scheduled로 저장하고 기존 publish-scheduled 작업이 공개한다.
검수가 끝나기 전에 발행 시각을 넘기면 새 기사를 공개하지 않고 보류한다.
PC 전원을 켜거나 ChatGPT 대화를 유지할 필요가 없다.

## 세계 자치모델
공식 지방정부·공공기관 도메인 검색 → 원문 다운로드 → 한 도시·제도 선정 → 한국어 기사 작성 → 별도 모델의 근거·중복 검수 → 예약 저장.
기존 제목과 출처 URL을 대조한다. 주차별 고유 키와 DB 실행 선점으로 중복 저장을 방지한다.
서로 다른 공식 원문 두 개 이상, 문단별 출처, 적용 한계 및 경기·인천에서 검토할 질문을 포함한다.
외부 이미지를 무단 복사하지 않고 저장소의 편집용 도안을 사용한다.
공식자료가 충분하지 않으면 발행을 보류한다.

## 특집 변경
제목에 단어가 일치해야 한다는 조건을 원문 대조로 바꾸었다.
별도 모델이 모든 근거가 같은 현안인지 확인하고, 각 원문의 확인 구절이 실제 본문에 있는지 코드로 검증한다.
이번 주 공식자료 최소 두 건, 최종 공식 원문 세 건 및 기존 독립 RSI 검수 기준은 유지한다.

## 점검 및 재실행
- 관리자 화면 /admin/health: 실행 결과와 오류.
- 로그인한 관리자·편집장만 /api/admin/editorial-automation 에서 최근 실행 상태 확인.
- 위 주소에 ?runKey=실행키 를 붙이면 보관한 초안·원문·검수 결과 확인.
- 실행키 예: global-local-governance:2026-11-16 또는 gyeonggi-feature:2026-11-21.
- 인증된 cron URL에 ?dryRun=1 을 붙여 원문 검색과 생성·검수만 검사할 수 있다. AI 사용 비용은 발생하지만 DB 저장·R2 업로드·기사 발행은 하지 않는다.
- 인증은 기존 CRON_SECRET Bearer 헤더. 키를 URL·저장소·대화에 넣지 않는다.
- Preview의 실제 예약 저장 요청은 차단한다.
- 보류된 초안은 site_config의 editorial:실행키에 보관한다. 운영 중 수정한 초안을 자동으로 공개하는 기능은 없다.

## 환경 및 복구
DATABASE_URL, CRON_SECRET 및 기존 Vercel AI Gateway 인증을 사용한다.
세계자치모델 모델은 WORLD_LOCAL_TEXT_MODEL, WORLD_LOCAL_REVIEW_MODEL로 변경할 수 있으며 기본값은 코드에 명시한다.
새 DB 마이그레이션은 필요 없다. 기존 weekly_feature_runs, articles.automation_key, site_config를 사용한다.

복구 소스는 GitHub 저장소에 보관한다. 새 PC에서는 해당 브랜치를 clone하고 npm ci로 실행 환경을 다시 만든다.
비밀키는 저장소에 넣지 않고 Vercel 설정에서 관리한다.
코드 백업과 별개로 기사 DB 및 R2 원본의 정기 백업은 별도로 구성해야 한다.

## 검증
npm run test:weekly-feature
npm run test:world-local
npx tsc --noEmit

scripts/verify-editorial-recovery.ts는 서버 환경에서 두 자동화를 dry-run으로 점검하는 수동 도구다.
기본 build나 예약 작업에서 자동 실행하지 않는다.
